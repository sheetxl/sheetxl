# Security Policy

## Reporting a vulnerability

If you believe you’ve found a security vulnerability in SheetXL, please report it privately.

Preferred:

- Use GitHub Security Advisories (repo → **Security** → **Report a vulnerability**) so we can coordinate a fix before public disclosure.

Alternate:

- Email `support@sheetxl.com` with subject line: `Security vulnerability report`

Please include:

- A clear description of the issue and potential impact
- Steps to reproduce (proof-of-concept if available)
- Affected package(s) and version(s)
- Any relevant logs, screenshots, or stack traces

## Our process

- We will acknowledge receipt.
- We will work with you on a reasonable timeline for a fix and coordinated disclosure.
- If the issue is confirmed, we will prioritize a patch and publish a release when available.

## Supported versions

SheetXL is a multi-package monorepo published to npm.

- We generally support the **latest released versions** of packages.
- If you can reproduce on the latest release, please include that information in the report.

## Public disclosure

Please do not open a public GitHub issue for security vulnerabilities.
Use the private reporting channels above.
